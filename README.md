# CFOP Rubik's Cube Solver

A pure-Python solver that solves any 3x3 scramble using the **CFOP** method
(Cross, F2L, OLL, PLL). It is built to produce human-style solutions: the
cross is combined with a first F2L pair when possible, F2L is solved
"intuitively", and the last layer uses OLL and PLL algorithms.

- No dependencies to run the solver (only `pytest` for the tests)
- A full solve takes about 0.2 seconds (the first solve is a few seconds slower,
  while a lookup table is built)
- Average solution: about 50 moves (30 to 62 over 300 random scrambles)

## Quick start

```bash
python solver.py                       # random 20-move scramble
python solver.py "R U R' F2 D' L B"    # your own scramble
```

Example output:


## Orientation and notation

Scrambles are applied to a cube held with:

| White top | Green front | Red right | Orange left | Yellow bottom | Blue back |
|---|---|---|---|---|---|

The solver then flips the whole cube with `x2` so it solves from:

| Yellow top | Blue front | Red right | Orange left | White bottom | Green back |
|---|---|---|---|---|---|

**All moves printed after the scramble are in this flipped orientation.**
The solver builds the white cross on the bottom.

Notation: `R U F L B D` are clockwise face turns, `'` is counter-clockwise, `2`
is a half turn. Rotations are `x y z`, slice moves are `M E S`, and wide moves
are `r l u d f b`.

## How it works

| Stage | What it does | Method |
|---|---|---|
| **Cross + pair** | Solves the white cross together with one F2L pair if the total is **8 moves or fewer**, otherwise the optimal plain cross | Bidirectional search over the tracked pieces |
| **F2L** | Solves the remaining corner-edge pairs without breaking the cross | Tiered "intuitive" search (below) |
| **OLL** | Orients the whole last layer with one algorithm | 57 generated algorithms, plus the best pre-turn of the top layer |
| **PLL** | Permutes the last layer with one algorithm | 21 standard algorithms, plus pre/post turns (AUF) |

### The cube model (`cube.py`)

The cube is 54 stickers, each identified by its 3D position and the direction
it faces. Every move is generated by rotating those coordinates, so there are
no hand-typed permutation tables to get wrong.

### Piece tracking

One sticker per piece is enough to know a piece's position and orientation.
Searches therefore work on a short tuple of slot numbers (for example the 4
cross edges, the pairs already solved, and the pair being solved) instead of the
whole cube.

### Cross and cross + pair (`cross.py`, `f2l.py`)

The cross has only 190,080 states, so the solver searches all of them once
(about 2.5 seconds, cached) and then solves any cross optimally (8 moves at
most). For cross + pair it runs a bidirectional search for each of the four
pairs and takes the shortest, if it is within 8 moves.

### F2L (`f2l.py`)

Pairs are solved in three tiers, each with a small penalty:

1. **Tier 1 (penalty 0):** only U and the slot's own two faces, the classic intuitive way
2. **Tier 2 (penalty 1):** U and any side face, still never the cross face
3. **Tier 3 (penalty 3):** anything, including the cross face (last resort)

The cheapest pair (length + penalty) is taken at each step, and every pair
comes with a plain-English description of where its corner and edge were.

### OLL (`oll.py`, `oll_table.py`, `build_oll.py`)

The 216 orientation states of the last layer fall into 57 OLL cases (plus
"solved") under top-layer turns. `build_oll.py` found a short algorithm for each
case by search, using R, U and F turns (and L or B only when that is shorter).
Algorithms are 6 to 12 moves. The case numbers shown are this solver's own
numbering, not the official OLL numbers.

### PLL (`pll.py`)

The 21 standard algorithms are each verified by simulation. A table of all 288
last-layer permutation states is built from them, so any state is solved with
the shortest combination of pre-turn, algorithm and post-turn.

## Project layout

```
cube.py          Cube model, moves, rotations, slice/wide moves, scramble generator
cross.py         Optimal cross solver
f2l.py           Cross + pair, humanised F2L, shared bidirectional search
ll_common.py     Shared last-layer helpers (keys, orientation states, move merging)
oll.py           OLL solver
oll_table.py     57 generated OLL algorithms (do not edit by hand)
build_oll.py     Regenerates oll_table.py by search (about 1 minute)
pll.py           PLL algorithms, table builder and solver
solver.py        Full pipeline and command-line entry point
test_*.py        Tests for each module
```

## Using it from Python

```python
from cube import Cube, random_scramble
from solver import solve_scramble, format_solution

scramble = random_scramble(20)
result = solve_scramble(scramble)

print(format_solution(result))
print(result["moves"])             # the full solution as one move list
print(result["cube"].is_solved())  # True
```

Smaller pieces can be used on their own:

```python
from cube import Cube, orient_for_solving
from cross import solve_white_cross
from f2l import solve_cross_and_pair, solve_f2l
from oll import solve_oll
from pll import solve_pll

cube = orient_for_solving(Cube().apply("R U R' U' F2 D L' B"))
first = solve_cross_and_pair(cube)     # {"moves": [...], "pair": "FR" or None}
```

`Cube().apply(...)` accepts either a string (`"R U R' U'"`) or a list of moves.
